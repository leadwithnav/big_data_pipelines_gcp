Step 1: Open Cloud Shell & Set Environment Variables

Activate Cloud Shell, set cluster/region/zone variables, authenticate, and configure your active project.

💡 Dataproc & YARN Overview
Google Cloud Dataproc is GCP's fully-managed Apache Spark and Hadoop service. YARN (Yet Another Resource Negotiator) acts as the cluster resource manager and job scheduler, allocating memory/CPU containers for Spark applications.

Before provisioning clusters, auto-detect your project ID, set environment variables (`PROJECT_ID`, `REGION`, `ZONE`, `CLUSTER_NAME`), and authenticate your session.

Linux / macOS (BASH) 
# Auto-detect your active GCP Project ID
export PROJECT_ID=$(gcloud config get-value project)

# Choose a region and zone
export REGION=us-central1
export ZONE=us-central1-a

# Define your cluster name
export CLUSTER_NAME="cluster-lab"

echo "Project ID   : $PROJECT_ID"
echo "Region       : $REGION"
echo "Zone         : $ZONE"
echo "Cluster Name : $CLUSTER_NAME"

gcloud auth login
gcloud config set project $PROJECT_ID
PowerShell (BASH) 
# Auto-detect active GCP Project ID in PowerShell
$env:PROJECT_ID=(gcloud config get-value project)

# Choose a region and zone
$env:REGION="us-central1"
$env:ZONE="us-central1-a"

# Define cluster name
$env:CLUSTER_NAME="cluster-lab"

Write-Host "Project ID   : $env:PROJECT_ID"
Write-Host "Region       : $env:REGION"
Write-Host "Zone         : $env:ZONE"
Write-Host "Cluster Name : $env:CLUSTER_NAME"

gcloud auth login
gcloud config set project $env:PROJECT_ID
  • Set Environment Variables Export PROJECT_ID, REGION, ZONE, and CLUSTER_NAME variables.
  • Authenticate & Set Project Run gcloud auth login and gcloud config set project.

Step 2: Create a Dataproc Cluster

Provision a cost-effective single-node Dataproc cluster with Component Gateway enabled.

⚡ Component Gateway
Enabling `--enable-component-gateway` provides secure web access to YARN ResourceManager, Jupyter, and other Hadoop UIs directly from your browser. Cluster creation typically takes 5 to 7 minutes.

Run `gcloud dataproc clusters create` using single-node mode with `n2-standard-4` machine type, Debian 12 image version, Jupyter, and Component Gateway enabled.

Linux / macOS (BASH) 
gcloud dataproc clusters create ${CLUSTER_NAME} \
    --region=${REGION} \
    --zone=${ZONE} \
    --single-node \
    --master-machine-type=n2-standard-4 \
    --image-version=2.2-debian12 \
    --enable-component-gateway \
    --optional-components=JUPYTER \
    --project=${PROJECT_ID}
PowerShell (BASH) 
gcloud dataproc clusters create $env:CLUSTER_NAME `
    --region=$env:REGION `
    --zone=$env:ZONE `
    --single-node `
    --master-machine-type=n2-standard-4 `
    --image-version=2.2-debian12 `
    --enable-component-gateway `
    --optional-components=JUPYTER `
    --project=$env:PROJECT_ID
  • Provision Single-Node Cluster Execute gcloud dataproc clusters create command.
  • Verify Cluster Status Confirm cluster state transitions to RUNNING in GCP Console.

Step 3: Open the YARN Resource Manager UI

Access the YARN ResourceManager web panel securely via Component Gateway.

🔍 YARN ResourceManager Panel
The YARN ResourceManager UI displays active node managers, container memory/vCPU allocations, and application execution logs in real-time.

Navigate to Dataproc → Clusters → click `cluster-lab` → Web Interfaces tab → click YARN ResourceManager. The dashboard will load showing 0 active/completed applications.

Linux / macOS (BASH)

Step 4: Submit a Spark Job from Cloud Shell

Submit a pre-packaged Spark Pi calculation job to the cluster.

🚀 Job Submission Engine
Submitting jobs via `gcloud dataproc jobs submit spark` sends the request to the master node, which delegates container allocation and task execution to YARN.

Run `gcloud dataproc jobs submit spark` referencing the built-in `SparkPi` example JAR located on the cluster master VM to calculate Pi with 1000 iterations.

Linux / macOS (BASH) 
gcloud dataproc jobs submit spark \
    --cluster=${CLUSTER_NAME} \
    --region=${REGION} \
    --project=${PROJECT_ID} \
    --class=org.apache.spark.examples.SparkPi \
    --jars=file:///usr/lib/spark/examples/jars/spark-examples.jar \
    -- 1000
PowerShell (BASH) 
gcloud dataproc jobs submit spark `
    --cluster=$env:CLUSTER_NAME `
    --region=$env:REGION `
    --project=$env:PROJECT_ID `
    --class=org.apache.spark.examples.SparkPi `
    --jars=file:///usr/lib/spark/examples/jars/spark-examples.jar `
    -- 1000
  • Submit SparkPi Job Run gcloud dataproc jobs submit spark command.
  • Observe Execution Logs Monitor job submission STDOUT in Cloud Shell terminal.

Step 5: Verify Application on YARN UI & Dataproc Jobs CLI

Trace Spark application lifecycle in YARN UI and inspect job status via gcloud Dataproc CLI.

📊 Job & YARN Application Verification
Observe the application transition from ACCEPTED → RUNNING → FINISHED in the YARN ResourceManager Web UI (via Component Gateway). You can also list and describe job details directly using `gcloud dataproc jobs` commands without needing SSH permissions.

Return to your YARN ResourceManager browser tab to verify `org.apache.spark.examples.SparkPi`. Alternatively, run `gcloud dataproc jobs list` and `gcloud dataproc jobs describe` in Cloud Shell to query job status and execution details.

Linux / macOS (BASH) 
# 1. List Dataproc jobs submitted to the cluster
gcloud dataproc jobs list --region=${REGION}

# 2. Inspect detailed job status and STDOUT/STDERR logs
gcloud dataproc jobs describe [JOB_ID] --region=${REGION}
PowerShell (BASH) 
# 1. List Dataproc jobs submitted to the cluster
gcloud dataproc jobs list --region=$env:REGION

# 2. Inspect detailed job status and STDOUT/STDERR logs
gcloud dataproc jobs describe [JOB_ID] --region=$env:REGION
  • Verify Spark Application State Confirm application state reaches FINISHED in YARN UI.
  • List Dataproc Jobs via CLI Run gcloud dataproc jobs list --region=${REGION}.
  • Describe Job Details Run gcloud dataproc jobs describe [JOB_ID] for logs.
