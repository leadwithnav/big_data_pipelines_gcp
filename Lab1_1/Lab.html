Step 3: Load `ratings.csv` into HDFS

Open JupyterLab Terminal and load `ratings.csv` into distributed HDFS storage.

📁 HDFS Storage Setup
Loading data into HDFS splits the file into blocks across worker nodes, enabling Spark to create distributed partitions for parallel execution.

In JupyterLab Launcher, open a **Terminal** session and run HDFS CLI commands to create `/data` and put `ratings.csv` into HDFS.

Linux / macOS (BASH) 
# Create a directory in HDFS (skip if /data was created in Lab 1)
hdfs dfs -mkdir -p /data

# Load ratings.csv from local workspace into HDFS
hdfs dfs -put ratings.csv /data/

# Verify the file is stored in HDFS
hdfs dfs -ls /data

Step 4: Open & Run PySpark Jupyter Notebook (`spark_architecture.ipynb`)

Execute PySpark transformations and observe partition behavior and shuffle boundaries.

⚡ PySpark Transformations & Shuffling
Narrow transformations (filter, map) do not shuffle data across nodes. Wide transformations (groupBy, join) trigger network shuffles across stage boundaries.

In JupyterLab file browser, double-click `spark_architecture.ipynb`, select **PySpark** kernel, and run cells sequentially to perform Spark transformations and actions.

Linux / macOS (PYTHON) 
from pyspark.sql import SparkSession
from pyspark.sql.functions import col

# 1. Initialize SparkSession
spark = SparkSession.builder \
    .appName("Lab1_1-Spark-Architecture-Exploration") \
    .getOrCreate()

# 2. Read ratings dataset from HDFS
df_ratings = spark.read.csv("hdfs:///data/ratings.csv", header=True, inferSchema=True)
print("Initial Partition Count:", df_ratings.rdd.getNumPartitions())

# 3. Narrow Transformation (Filter - No Shuffle)
high_ratings = df_ratings.filter(col("rating") >= 4.0)

# 4. Wide Transformation (GroupBy - Triggers Shuffle Stage Boundary)
avg_user_ratings = high_ratings.groupBy("userId").avg("rating")
avg_user_ratings.show(5)
PowerShell (PYTHON)

Step 5: Explore Jobs, Stages & Tasks in Spark UI

Inspect the Spark Application UI / History Server to analyze DAG execution details.

🌐 Spark Application UI & DAG Inspector
The DAG Scheduler visualizes Jobs, Stages, Shuffle read/write metrics, and parallel Tasks per partition.

Navigate to Google Cloud Console → Dataproc → Clusters → `cluster-lab` → Web Interfaces tab → click Spark History Server or Spark Application UI: 1. Locate your session `Lab1_1-Spark-Architecture-Exploration`. 2. **Jobs Tab**: Each action (`.count()`, `.show()`) triggers a separate Job. 3. **Stages Tab**: Filter ran in 1 Stage (no shuffle); GroupBy ran in 2 Stages (shuffle boundary). 4. **Tasks Detail**: Task count matches partition count.
