Step 1: GCS Bucket & Connection IAM Authorization

Create Cloud Storage bucket and grant BigQuery Connection service account IAM permissions.

💡 BigQuery Managed Iceberg
BigQuery Managed Iceberg Tables combine BigQuery's SQL execution engine with Apache Iceberg open storage format on Cloud Storage.

Create GCS warehouse bucket and grant Storage Object Admin role to BigQuery Connection SA.

Linux / macOS (BASH) 
gsutil mb -l us-central1 gs://[YOUR_PROJECT_ID]-bq-iceberg-warehouse
gcloud max-file-size=5G ...
PowerShell (BASH) 
gsutil mb -l us-central1 gs://[YOUR_PROJECT_ID]-bq-iceberg-warehouse
gcloud max-file-size=5G ...
  • Create Warehouse Bucket Create gs://[PROJECT_ID]-bq-iceberg-warehouse bucket.
  • Authorize Connection IAM Grant Storage Object Admin to Connection Service Account.

Step 2: Creating BigQuery External Connection

Provision BigQuery Cloud Resource Connection for Apache Iceberg.

🔗 Cloud Resource Connection
BigQuery uses Cloud Resource Connections to securely authenticate and write Iceberg metadata files directly to GCS buckets.

Create connection `bq-iceberg-connection` in region `us-central1`.

Linux / macOS (BASH) 
gcloud components update
gcloud bigquery connections create cloud-resource \
  --location=us-central1 \
  bq-iceberg-connection
PowerShell (BASH) 
gcloud components update
gcloud bigquery connections create cloud-resource `
  --location=us-central1 `
  bq-iceberg-connection
  • Create Cloud Connection Run gcloud bigquery connections create command.
  • Retrieve SA Email Extract serviceAccountId from connection describe output.

Step 3: Provisioning BigQuery Managed Iceberg Table

Execute SQL DDL to create Managed Iceberg Table on GCS.

🏗️ Table Format: ICEBERG
Specifying `table_format='ICEBERG'` and linking your GCS connection creates native Apache Iceberg storage files managed by BigQuery.

Execute SQL DDL statement in BigQuery SQL workspace.

Linux / macOS (SQL) 
CREATE OR REPLACE TABLE sensor_analytics.managed_iceberg_sensors (
  device_id STRING,
  timestamp TIMESTAMP,
  temperature DOUBLE,
  status STRING
)
WITH CONNECTION `us-central1.bq-iceberg-connection`
OPTIONS (
  file_format = 'PARQUET',
  table_format = 'ICEBERG',
  storage_uri = 'gs://[YOUR_PROJECT_ID]-bq-iceberg-warehouse/tables/managed_iceberg_sensors'
);
PowerShell (SQL) 
CREATE OR REPLACE TABLE sensor_analytics.managed_iceberg_sensors (
  device_id STRING,
  timestamp TIMESTAMP,
  temperature DOUBLE,
  status STRING
)
WITH CONNECTION `us-central1.bq-iceberg-connection`
OPTIONS (
  file_format = 'PARQUET',
  table_format = 'ICEBERG',
  storage_uri = 'gs://[YOUR_PROJECT_ID]-bq-iceberg-warehouse/tables/managed_iceberg_sensors'
);
  • Execute Table Creation DDL Run CREATE TABLE WITH CONNECTION statement.
  • Verify GCS Files Inspect metadata/ and data/ directories in GCS bucket.

Step 4: Transactional DML (INSERT, UPDATE, DELETE, MERGE)

Execute ACID transactional SQL queries directly on BigQuery Managed Iceberg Table.

🔄 Full DML Capabilities
Unlike standard read-only external tables, BigQuery Managed Iceberg tables support full SQL DML statements (INSERT, UPDATE, DELETE, MERGE).

Run DML operations directly in BigQuery Studio.

Linux / macOS (SQL) 
-- Insert Data
INSERT INTO sensor_analytics.managed_iceberg_sensors VALUES ('dev_01', current_timestamp(), 72.4, 'OK');

-- Update Data
UPDATE sensor_analytics.managed_iceberg_sensors SET status = 'WARNING' WHERE temperature > 70.0;

-- Delete Data
DELETE FROM sensor_analytics.managed_iceberg_sensors WHERE status = 'OK';
PowerShell (SQL) 
-- Insert Data
INSERT INTO sensor_analytics.managed_iceberg_sensors VALUES ('dev_01', current_timestamp(), 72.4, 'OK');

-- Update Data
UPDATE sensor_analytics.managed_iceberg_sensors SET status = 'WARNING' WHERE temperature > 70.0;

-- Delete Data
DELETE FROM sensor_analytics.managed_iceberg_sensors WHERE status = 'OK';
  • Run INSERT DML Execute INSERT INTO statement.
  • Run UPDATE & DELETE DML Execute UPDATE and DELETE statements.

Step 5: Time Travel & Teardown

Execute time travel queries in BigQuery and clean up resources.

🧹 Resource Teardown
Drop table and connection after completing verification.

Query historical table states using `FOR SYSTEM_TIME AS OF`.

Linux / macOS (SQL) 
-- Time Travel Query
SELECT * FROM sensor_analytics.managed_iceberg_sensors FOR SYSTEM_TIME AS OF TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 5 MINUTE);
PowerShell (SQL) 
-- Time Travel Query
SELECT * FROM sensor_analytics.managed_iceberg_sensors FOR SYSTEM_TIME AS OF TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 5 MINUTE);
  • Execute Time Travel Query Run FOR SYSTEM_TIME AS OF query in BQ Studio.
  • Teardown Resources Drop table and connection.
